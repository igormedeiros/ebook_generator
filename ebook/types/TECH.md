# Tipo de E-book: Técnico (TECH)

## 1. Proporção de Conteúdo
- **Prática (70%):** Código, diagramas, explicações técnicas, "como fazer".
- **Teoria (30%):** Conceitos, "por que", decisões de arquitetura, ética.

## 2. Padrões de Código
- **Linguagem:** Preferencialmente Python (conforme expertise do autor).
- **Estilo:** Código limpo, com Type Hints e comentários essenciais.
- **Explicação:** Todo bloco de código deve ser precedido por um problema e seguido por uma dissecação técnica.

## 3. Elementos Didáticos
- **Cicatrizes de Produção:** Seções de "Atenção" ou "Dica de Especialista" baseadas em falhas reais.
- **Hands-on:** Desafios práticos para o leitor ao final de seções complexas.
- **Zero Atalhos:** Não usar bibliotecas "mágicas" sem explicar o que ocorre sob o capô.

## 4. Perfil do Leitor
- Desenvolvedores Plenos e Seniores que buscam profundidade profissional e aplicação prática na vida real.

## 5. Personas de Revisão Obrigatórias (Master Subset)
Para este tipo, as seguintes personas de `REVIEWS.md` são mandatórias:
1. **The Programmer** 💻 (Código e Padrões)
2. **The Code Tester** ⚙️ (Validação Funcional)
3. **The Teacher** 🎓 (Fluxo Didático)
4. **The Cautious One** ⚠️ (Segurança e Riscos)
5. **The Illustrator** 🎨 (Visualização técnica)
6. **The Validator** ✅ (Padrões de Mercado)
7. **The Markdown Editor** 📝 (Estrutura de blocos de código)
*Observação: Outras personas (como The Philosopher ou The Writer) podem ser adicionadas se o AUTHOR_STYLE.md exigir uma abordagem mais humanizada.*
